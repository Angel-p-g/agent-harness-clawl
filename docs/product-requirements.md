## 1. 背景与问题

网络信息并不稀缺，稀缺的是**可复核的证据链**。

- 同一新闻事件会被大量站点转载、改写、拼接，原始来源和传播路径被淹没。
- 搜索引擎返回链接列表，不回答「谁最先报道」「哪些来源真正独立」「哪些说法互相矛盾」。
- 人工溯源依赖分析师逐个打开页面、比对时间、记录引用，成本高且难以复用。
- 一次性抓取结果通常散落在脚本和表格里，无法沉淀为可查询、可版本化的数据资产。
- 用户往往只给出模糊目标，例如「过去三个月某行业的供应链风险」，无法直接转化为抓取计划与字段设计。

因此，产品需要同时解决三类问题：

1. **深度采集**：从模糊需求出发，规划并并发抓取海量公开网页。
2. **事件归因**：抽取事实、构建时间线与信源谱系，给出有证据等级的因果假设。
3. **资产化交付**：把过程和结果沉淀为可复用的数据集，或生成用户指定的数据报表。

## 2. 产品定义与愿景

用户提出一个模糊问题，系统将其转化为可执行的研究计划，在预算内并发采集公开网络信息，抽取事实与证据，构建事件时间线和信源谱系，最终输出带引用、置信度和替代解释的事件档案、数据集或报表。

产品提供三种一等交付物：

| 交付物 | 说明 | 典型使用者 |
|---|---|---|
| 事件档案 | 事件摘要、时间线、参与方、信源谱系、证据表、因果假设与置信度 | 记者、研究员、风控分析师 |
| 数据资产 | 结构化、去重、版本化、带血缘关系的数据集，可查询、可增量更新 | 数据团队、开发者 |
| 数据报表 | 按模板生成的可引用报告，支持定时刷新与变化对比 | 业务、运营、管理层 |

产品原则：

1. **证据优先。** 报告中的每个事实陈述都能回溯到文档与原文片段。
2. **溯源优先于数量。** 十个转载同一通稿的站点，不等于十个独立信源。
3. **归因是假设，不是判决。** 明确区分相关、时序先验、机制证据与反事实证据。
4. **资产可复用。** 原始快照与结构化结果都保留血缘，新任务优先复用已有资产。
5. **合规与安全内建。** 只采集公开可访问内容，尊重站点策略与版权边界。
6. **人在回路。** 高影响、低置信度的归因必须进入人工复核。

## 3. 目标用户与核心场景

| 用户 | 核心诉求 | 成功标准 |
|---|---|---|
| 调查记者 / 研究员 | 快速还原事件时间线，找到最早来源与独立佐证 | 能在一份档案中完成初步核实 |
| 数据分析师 | 把一次研究沉淀为可复用数据集 | 新任务无需重复抓取与清洗 |
| 风控 / 业务分析师 | 持续监测某主题并生成定期简报 | 变化可追踪、结论可引用 |
| 开发者 / 数据工程师 | 扩展来源、抽取器、归因策略与报表模板 | 通过插件接入，不改核心包 |

核心场景：

### 场景 A：新闻事件溯源

用户输入：「某地某事件最早的报道是什么？过去两周各方说法有哪些变化？哪些信息互相矛盾？」

系统输出事件档案：事件摘要、时间线、首发来源、转载与引用链、独立信源矩阵、矛盾点、待核实问题、因果假设及证据等级。

### 场景 B：模糊需求转数据资产

用户输入：「帮我看看近半年新能源车企的供应链风险，整理成可以复用的数据。」

系统先澄清行业范围、地区、时间窗、关注字段与输出格式，再执行采集、抽取、去重与归一化，最终产出带字段说明、来源血缘和版本号的数据集。

### 场景 C：持续监测与报表

用户输入：「每周一生成一份某主题的舆情与事件简报。」

系统按计划增量抓取，检测新事件与说法变化，生成带引用的周报，并把新增数据合并进既有资产。

## 4. 产品范围与非目标

### 4.1 范围内

- 公开可访问的新闻站点、博客、机构网站、公开文档与用户提供的种子 URL。
- 并发抓取、增量抓取、断点续跑、失败重试与预算控制。
- 正文抽取、元数据抽取、实体与声明抽取、去重与规范化。
- 事件聚类、时间线、信源谱系、跨源佐证、矛盾检测。
- 有证据等级的因果假设与替代解释。
- 数据集、报表、查询接口与定时监测。
- 人工复核、审计日志与结果导出。

### 4.2 非目标

- 不绕过付费墙、登录、验证码或其他访问控制。
- 不采集非公开数据、个人隐私数据或受法律限制的数据。
- 不把系统输出当作法律、医疗、金融事实的最终裁决。
- MVP 不做全网实时社媒 firehose 与全量搜索引擎。
- 不做无人审核的自动发布或自动指控。
- 不追求「一键给出唯一真相」；目标是给出可复核的证据与假设空间。

## 5. 核心概念与数据模型

| 概念 | 定义 |
|---|---|
| Job | 一次用户任务，包含原始需求、预算、状态与交付物引用 |
| Brief | 结构化研究简报：问题、实体、时间窗、地域、来源约束、输出格式 |
| Source | 站点或发布者，记录域名、所有权、来源类型与策略元数据 |
| Document | 一次抓取的页面或文件，保留 URL、 canonical URL、抓取时间、内容哈希与原始快照 |
| Claim | 可独立核验的最小事实陈述，必须绑定文档与原文片段 |
| Entity | 人物、组织、地点、产品等实体 |
| Event | 由多条 Claim 聚合出的事件，包含参与方、时间、地点与状态 |
| Evidence | Claim 与 Document、来源独立性、立场、时间一致性的关联 |
| Attribution | 对事件来源、传播路径或因果假设的归因结论，带证据与置信度 |
| Dataset | 可版本化、可查询、带血缘的结构化数据资产 |
| Report | 基于 Dataset 与事件档案生成的报表，所有事实陈述带引用 |

数据流：

```text
Job → Brief → Plan → Frontier → Documents → Claims → Events
                                      │         │
                                      └→ Evidence ←┘
                                             ↓
                                 Attribution graph
                                             ↓
                                     Dataset / Report
```

### 5.1 证据等级

| 等级 | 含义 | 示例 |
|---|---|---|
| E0 | 未验证 | 单一匿名说法，无原文或无法访问 |
| E1 | 单一来源 | 只有一个可访问来源，尚未交叉验证 |
| E2 | 多源独立佐证 | 至少两个相互独立的来源给出一致说法 |
| E3 | 原始材料支持 | 官方文件、数据集、现场记录、原始影像等一手材料 |
| E4 | 人工复核 | 分析师复核并记录判断依据 |

### 5.2 归因等级

| 等级 | 含义 | 产品呈现 |
|---|---|---|
| A0 | 相关 | 仅存在统计或文本关联，不主张因果 |
| A1 | 时序与机制 | 时间先后成立，且有可解释机制，但仍可能有混杂因素 |
| A2 | 多源独立证据 | 多个独立来源或材料支持同一因果假设 |
| A3 | 反事实 / 干预证据 | 有对照、自然实验或反事实检验支持 |

系统默认只输出 A0–A1；达到 A2 需要独立证据矩阵；A3 必须人工复核并在报告中标注方法与局限。

## 6. 功能需求

优先级：**P0** 为 MVP 必须；**P1** 为首个可用版本；**P2** 为规模化增强。

### FR-1 任务接入与澄清（P0）

- 接受自然语言需求、种子 URL、文件或定时任务。
- 将需求解析为 Brief：研究问题、实体、时间窗、地域、来源范围、输出格式、预算与截止时间。
- 对模糊需求主动提出不超过 3 个关键澄清问题；用户可选择「自动决策」跳过。
- 在用户确认 Brief 前不启动大规模抓取。

验收：

- 给定一段模糊需求，系统能产出结构化 Brief，并列出假设与待确认项。
- Brief 可编辑、可保存为模板，后续任务可复用。
- 超出预算或合规边界的请求被拒绝，并给出可执行建议。

### FR-2 研究规划与源发现（P0）

- 生成查询变体、候选来源、抓取优先级与停止条件。
- 评估来源类型、覆盖度、更新频率与预期成本。
- 计划中明确页面量、token、带宽与时间预算。

验收：

- 计划包含来源清单、优先级、估算成本与停止条件。
- 用户可在执行前调整来源范围与预算。
- 计划变更记录在 Job 审计日志中。

### FR-3 并发抓取与调度（P0）

- 维护待抓取 Frontier，支持优先级、去重与增量更新。
- 支持全局并发与每主机并发/QPS 限制，遵守 `robots.txt` 与站点条款。
- 支持超时、重试与指数退避，尊重 `Retry-After`。
- 支持断点续跑、暂停/恢复、失败队列与死信队列。
- 支持静态 HTML 与可配置的动态渲染；非 HTML 内容按类型处理。
- 对 URL 做规范化，对内容做哈希与近似去重。

验收：

- 并发数、每主机速率、超时与预算均可配置。
- 进程中断后可从检查点恢复，不重复抓取已完成 URL。
- 对 `429`、`5xx` 与网络错误有明确的重试与放弃策略。
- 同一任务内不会因转载页重复计入独立来源。

### FR-4 内容抽取与规范化（P0）

- 抽取标题、作者、发布时间、语言、正文、引用、表格与关键元数据。
- 将 HTML 转为纯文本 / Markdown，保留段落与原文定位信息。
- 抽取实体、声明、引语与数字指标；低置信度结果显式标记。
- 保留原始快照与抽取版本，支持重新处理。

验收：

- 每条 Claim 都能定位到 Document 的具体片段。
- 抽取结果包含语言、时间、来源与置信度。
- 正文抽取失败时保留原始快照并进入失败队列，而不是静默丢弃。

### FR-5 事件抽取与时间线（P0）

- 将文档聚类为事件，合并同一事件的不同报道。
- 抽取事件类型、参与方、时间、地点、状态与关键数字。
- 生成时间线，标注首次出现、更新时间与矛盾说法。
- 支持事件合并、拆分与人工修正。

验收：

- 事件档案包含时间线、参与方、来源列表与未解决问题。
- 同一事件的多篇转载不会被展示为多个独立事件。
- 时间线中的每个节点都有来源与时间戳。

### FR-6 信源谱系与传播溯源（P0）

- 识别首发来源、转载、改写、引用与删除/更新。
- 构建来源传播图：谁引用了谁、何时引用、引用了哪些片段。
- 评估来源独立性：同一通讯社、同一集团、同一通稿视为相关来源。
- 输出每个 Claim 的最早已知来源、下游传播链与独立佐证数量。

验收：

- 对每个核心 Claim，能回答「最早出现在哪里」「哪些是转载」「哪些是独立佐证」。
- 传播图可导出为 JSON / 可视化数据。
- 来源独立性判断附理由，而不是仅按域名计数。

### FR-7 因果假设与归因（P1）

- 基于事件图、时间顺序、机制解释与独立证据，提出候选原因。
- 对每个候选原因给出支持证据、反证、替代解释与置信度。
- 明确标注归因等级（A0–A3），禁止把相关性表述为确定因果。
- 支持反事实检查：如果移除某因素，事件是否仍会发生？
- 将无法解释的矛盾与证据缺口列入「待核实」。

验收：

- 归因报告至少包含一个主假设与一个替代假设（存在歧义时）。
- 每个假设都有证据引用、置信度与可能被推翻的条件。
- 高影响结论必须进入人工复核，复核记录可审计。

### FR-8 人工复核（P1）

- 提供复核队列：低置信度、高影响、来源冲突、合规风险。
- 支持批准、驳回、修改、补充证据与标注理由。
- 记录复核人、时间、修改内容与最终结论。

验收：

- 所有 E4 结论都有复核记录。
- 复核修改会保留原始版本，不覆盖历史。

### FR-9 数据资产（P1）

- 维护数据集目录：字段 schema、版本、来源血缘、质量指标与更新时间。
- 支持增量更新、回填与重新抽取，不重复抓取原始页面。
- 支持查询 API 与导出（JSONL / CSV / Parquet）。
- 数据集可被新任务直接引用，避免重复建设。

验收：

- 新任务可声明复用已有数据集，并记录引用关系。
- 数据集版本可复现：同一版本对应固定的文档快照与抽取版本。
- 导出结果包含字段说明、来源与生成时间。

### FR-10 报表与交付（P1）

- 支持事件档案、数据集摘要、监测简报等模板。
- 报告中的事实陈述必须带引用；引用可解析到原文片段。
- 支持 Markdown / JSON / CSV 交付；PDF / HTML 作为后续增强。
- 报表可重复生成，输入数据版本与模板版本可追溯。

验收：

- 报告引用解析率 100%。
- 同一 Dataset + 模板 + 版本可生成一致报告。
- 用户可指定章节、指标、图表与时间范围。

### FR-11 持续监测与告警（P2）

- 支持定时任务与增量抓取，检测新事件、说法变化与来源删除。
- 支持阈值告警与摘要推送。
- 监测任务与一次性任务共享同一套资产与归因流水线。

验收：

- 新增事件能被识别并关联到既有事件或新建事件。
- 变化检测包含「新增、修改、删除、反转」四类。
- 告警包含证据链接与置信度。

### FR-12 插件与扩展（P1）

- 新来源适配器、抽取器、归因策略、报表模板均以 Cordis 插件接入。
- 插件通过 `inject` 声明依赖，通过事件扩展流水线，通过 `ctx.effect` 保证可逆。
- 核心包不感知具体站点、模型或存储实现。

验收：

- 新增一个来源适配器不需要修改核心包。
- 卸载插件后，其注册的工具、监听器与定时器全部撤销。
- 插件有契约测试与最小示例。

## 7. 典型用户流程

### 7.1 新闻事件溯源

1. **输入**：用户描述事件，或给出若干新闻链接。
2. **澄清**：系统确认时间窗、地域、关注问题与输出格式。
3. **规划**：生成检索词、候选来源、抓取预算与停止条件。
4. **采集**：并发抓取新闻页、转载页、机构公告与相关公开材料。
5. **抽取**：抽取正文、时间、作者、实体、声明与引语。
6. **聚类**：合并同一事件，识别转载与同源内容。
7. **溯源**：构建首发来源、传播链与独立信源矩阵。
8. **归因**：提出候选原因、替代解释、证据等级与待核实项。
9. **交付**：生成事件档案；用户可复核、导出或转为持续监测。

事件档案的建议结构：

```text
摘要
关键结论（带证据等级）
时间线
参与方与地点
信源谱系（首发 / 转载 / 独立佐证）
矛盾与未解决问题
因果假设（支持证据 / 反证 / 置信度 / 推翻条件）
引用列表
```

### 7.2 模糊需求转数据资产 / 报表

1. **输入**：「近半年某行业供应链风险，整理成可复用数据。」
2. **Brief**：系统提出行业边界、地区、时间窗、字段、输出格式等澄清项。
3. **计划**：列出候选来源、抓取量、预算与交付格式。
4. **执行**：并发采集、抽取、去重、归一化，写入暂存资产。
5. **质检**：检查字段完整率、来源覆盖、重复率与时间一致性。
6. **资产化**：生成带 schema、版本、血缘与质量指标的数据集。
7. **报表**：按用户模板生成摘要、图表与引用。
8. **复用**：后续任务可直接查询该资产，或设置定时增量更新。

## 8. 与 dsh-mini / Cordis 的映射

产品能力不进入核心包，而是以 bundle / profile 与插件叠加：

```text
profile: research
  ├─ bundle: base            # context、session、prompt、tools、agent loop
  ├─ bundle: crawl           # frontier、fetcher、policy、extractor
  ├─ bundle: attribution     # event graph、source lineage、causal hypotheses
  ├─ bundle: assets          # dataset catalog、query、export
  └─ bundle: reporting       # templates、renderers、delivery
```

建议的服务与事件边界：

| 产品能力 | 建议服务键 | 建议事件 |
|---|---|---|
| 任务接入与澄清 | `ctx.intake` | `job/created`、`job/needs-input`、`job/planned` |
| 研究规划 | `ctx.planner` | `plan/updated` |
| 抓取前沿与调度 | `ctx.frontier` | `crawl/queued`、`crawl/started`、`crawl/finished` |
| 抓取策略与安全 | `ctx.policy` | `crawl/pre-fetch`、`crawl/rejected` |
| 内容抽取 | `ctx.extractors` | `extract/pre-claim`、`extract/claim` |
| 事件图 | `ctx.eventGraph` | `event/upserted`、`event/merged` |
| 归因 | `ctx.attribution` | `attribution/proposed`、`attribution/verified` |
| 数据资产 | `ctx.assets` | `asset/updated`、`asset/versioned` |
| 报表 | `ctx.reports` | `report/rendered` |
| 人工复核 | `ctx.review` | `review/requested`、`review/resolved` |

实现约束沿用 [架构设计](architecture.md)：

- 一切皆插件；抓取、抽取、归因、存储、报表均可替换。
- 消费者依赖服务键与事件契约，不依赖具体 provider。
- 注册项通过 `ctx.effect` / `ctx.on` 安装，插件卸载自动回滚。
- 模型可见的每个决策都能从 session log 重建，便于审计与回放。

## 9. 非功能需求

### 9.1 性能与规模

- 全局并发、每主机并发、QPS、超时与重试均可配置。
- MVP 建议目标：单实例日抓取 1 万–10 万页；规模化阶段支持水平扩展至百万页/日。
- 支持增量抓取与缓存，避免重复下载未变化页面。
- 抓取与抽取解耦，任一侧可独立扩容。

### 9.2 可靠性与可恢复性

- 任务检查点、断点续跑、幂等写入与失败重放。
- 抓取、抽取、归因、报表各阶段都有独立状态与错误分类。
- 死信队列保留失败原因与原始输入，支持人工重试。

### 9.3 数据质量

- Claim 级来源定位；无法定位的陈述不得进入最终报告。
- 去重覆盖 URL、canonical URL、内容哈希与近似文本。
- 时间、语言、作者、来源类型等字段有明确缺失标记。
- 数据集带质量指标：完整率、重复率、来源覆盖度、时间一致性。

### 9.4 合规、安全与伦理

- 只访问公开内容，遵守 `robots.txt`、站点条款与版权限制。
- 不绕过登录、付费墙、验证码或访问控制。
- 默认只保存必要片段与元数据；全文存储需符合授权与保留策略。
- 防止 SSRF：限制协议、拒绝内网地址、限制重定向与响应体大小。
- 对个人信息做最小化处理；敏感场景进入人工复核。
- 报告披露来源局限、采样偏差与未解决问题，避免把假设包装成结论。

### 9.5 可观测性与成本

- 任务级指标：抓取量、成功率、抽取成功率、事件数、引用解析率、成本。
- 全链路 trace：从 Job 到 Document、Claim、Event、Report 可追溯。
- 每个任务有 token、带宽、存储与时间预算；超预算时暂停或降级。
- 模型、提示词、抽取器与归因策略均有版本号。

### 9.6 易用性

- 模糊需求可通过对话逐步澄清，不要求用户先写复杂查询。
- 默认提供安全的自动决策模式，同时保留手动确认。
- 交付物默认可读、可引用、可下载；失败时给出可执行的下一步。

## 10. 成功指标

以下为建议目标，需在真实数据上校准基线。

| 指标 | 定义 | 建议目标 |
|---|---|---|
| 引用解析率 | 报告中可解析到原文片段的引用占比 | 100% |
| Claim 溯源覆盖率 | 带文档与片段定位的 Claim 占比 | ≥ 95% |
| 独立信源覆盖 | 事件档案中独立来源数量中位数 | ≥ 3（可得时） |
| 事件时间线准确率 | 人工评估的时间线正确率 | ≥ 85% |
| 高置信归因精确率 | 高置信结论经复核为正确的比例 | ≥ 90% |
| 允许页面抓取成功率 | 排除合规拒绝后的成功抓取占比 | ≥ 95% |
| 数据资产复用率 | 新任务复用既有资产的比例 | ≥ 30% |
| 报表采纳率 | 用户接受或少量修改后使用的报告占比 | ≥ 80% |
| 单任务成本 | 单份事件档案或报表的平均成本 | 在预算内 |

## 11. 分期交付

### MVP（P0）

- 自然语言任务接入与 Brief 澄清。
- 研究计划、来源发现、并发抓取、预算与断点续跑。
- 正文与元数据抽取、Claim 级来源定位、去重。
- 事件聚类、时间线、首发来源与转载链。
- 基础事件档案与 Markdown / JSON 交付。
- 合规策略、审计日志与基础可观测性。

MVP 验收：给定一个新闻事件问题，系统能在预算内产出一份带时间线、来源谱系与引用的档案；每条结论可回溯到原文片段。

### Phase 2（P1）

- 因果假设、替代解释、归因等级与证据矩阵。
- 人工复核队列。
- 数据资产目录、版本、血缘、查询与导出。
- 报表模板、图表与定时刷新。
- 来源适配器、抽取器、归因策略的插件化扩展。

验收：同一份数据资产可被新任务复用；归因报告包含置信度与推翻条件；资产版本可复现。

### Phase 3（P2）

- 水平扩展与百万页/日规模。
- 多语言、多模态（图片、视频、附件）与跨语言事件对齐。
- 持续监测、变化检测与告警。
- 更丰富的因果方法：自然实验、对照比较、敏感性分析。
- 面向团队的权限、协作与交付集成。

## 12. 风险与开放问题

| 风险 | 影响 | 对策 |
|---|---|---|
| 站点反爬或结构变化 | 抓取失败、覆盖不足 | 每主机限速、官方 API 优先、适配器隔离、失败监控 |
| 同源转载被误判为独立信源 | 归因过度自信 | 内容指纹、通稿识别、来源所有权元数据、引用链分析 |
| LLM 抽取或归因幻觉 | 错误结论 | Claim 级引用、证据等级、复核、模型与提示词版本化 |
| 把相关误写成因果 | 误导用户 | 归因等级、替代解释、反事实检查、高影响结论人工复核 |
| 版权与合规风险 | 法律与声誉风险 | 只存必要片段、遵守 robots/条款、保留策略、法务评估 |
| 成本失控 | 预算超支 | 任务预算、增量抓取、采样、缓存、成本告警 |
| 来源偏差 | 结论不具代表性 | 来源多样性指标、披露采样局限、主动补充对立来源 |
| 数据漂移 | 历史资产失真 | schema 版本、血缘、重抽取、质量回归测试 |

待确认问题：

1. 首批聚焦的行业与地域是什么？新闻、金融、供应链还是科技？
2. 需要支持哪些语言？是否要求跨语言事件对齐？
3. 交付优先级是事件档案、数据集还是定时报表？
4. 部署形态是云端、私有化还是混合？数据保留周期与访问控制要求？
5. 可接受的单任务预算与并发规模是多少？
6. 人工复核由谁执行？SLA 与升级路径是什么？
7. 是否需要对接现有数据仓库、BI 或工单系统？
8. 对因果推理的方法与披露深度有何合规或编辑要求？

## 13. 术语表

- **事件归因**：回答事件何时、何地、由谁引发、如何传播、可能原因是什么，并给出证据与置信度；不是单一判决。
- **信源谱系**：记录首发、转载、引用、改写与删除关系的有向图。
- **独立信源**：在所有权、采编与信息获取上相互独立的来源；同一通稿的多个转载不算独立。
- **Claim**：可独立核验的最小事实陈述，必须绑定原文片段。
- **数据资产**：可发现、可查询、可版本化、带血缘与质量指标的结构化数据集。
- **证据等级**：E0–E4，表示从未验证到人工复核的证据强度。
- **归因等级**：A0–A3，表示从相关到反事实证据的因果支持强度。
